# tkdrop

노트북 두 대(Windows) 사이에서 **블루투스만으로** 작은 파일과 클립보드 텍스트를 주고받는 트레이 프로그램입니다.
인터넷이나 같은 LAN이 필요 없고, 설치 없이 `tkdrop.exe` 하나로 실행됩니다.

- 트레이에 상주하며, 받는 쪽은 **수락 없이 자동 저장** (기본 위치: `바탕화면\tkdrop`)
- 보내기: 트레이 아이콘 더블클릭 → 창에 파일/폴더를 끌어다 놓기, 또는 메뉴에서 `파일 보내기…` / `클립보드 텍스트 보내기`
- 받은 텍스트는 자동으로 클립보드에 복사되고 알림이 뜹니다
- 선택한 상대 노트북 외의 장치가 연결하면 거부합니다
- 전송 데이터는 SHA-256으로 검증합니다

## 다운로드

1. 이 저장소의 **Actions** 탭 → 최근 `build` 실행 → 아래 **Artifacts**의 `tkdrop` 을 내려받아 압축을 풉니다.
2. 또는 **Releases** 페이지에서 `tkdrop.exe` 를 내려받습니다. (태그 `v1.0.0` 처럼 `v*` 태그를 푸시하면 자동으로 릴리스가 만들어집니다.)

요구 사항: Windows 10 (1903 이상) 또는 Windows 11. .NET Framework 4.8 이 기본 포함되어 있어 따로 설치할 것이 없습니다.

## 처음 설정 (한 번만)

1. 두 노트북을 Windows **설정 → Bluetooth 및 장치** 에서 서로 페어링합니다.
2. 두 노트북 모두에서 `tkdrop.exe` 를 실행합니다. (트레이에 아이콘이 생깁니다)
3. **한쪽 노트북**에서 트레이 아이콘 우클릭 → `상대 노트북 선택…` → 상대를 고릅니다.
4. 그 노트북에서 아무 파일이나 한 번 보내면, 받는 쪽은 보낸 노트북을 **자동으로 상대로 등록**합니다.
   (원하면 받는 쪽에서도 `상대 노트북 선택…` 으로 직접 고를 수 있습니다.)

## 사용법

| 하고 싶은 일 | 방법 |
|---|---|
| 파일/폴더 보내기 | 트레이 아이콘 더블클릭 → 창에 끌어다 놓기 (여러 개, 폴더 가능) |
| 파일 보내기 (대화상자) | 트레이 메뉴 `파일 보내기…` |
| 클립보드 텍스트 보내기 | 트레이 메뉴 `클립보드 텍스트 보내기` (URL 복사해서 넘길 때) |
| 받은 파일 보기 | 트레이 메뉴 `받은 폴더 열기`, 또는 수신 알림 클릭 |
| 저장 위치 바꾸기 | 트레이 메뉴 `저장 폴더 변경…` |
| 부팅 시 자동 실행 | 트레이 메뉴 `Windows 시작 시 자동 실행` 체크 |
| 탐색기 "보내기" 메뉴에 넣기 | `Win+R` → `shell:sendto` → 그 폴더에 `tkdrop.exe` 바로가기 생성 |

명령줄: `tkdrop.exe 파일1 파일2 …` 는 바로 전송하고 끝나면 닫힙니다. `tkdrop.exe --text` 는 클립보드 텍스트를 보냅니다.

설정은 exe 옆 `tkdrop.settings.json` 에 저장됩니다 (exe 폴더에 쓸 수 없으면 `%APPDATA%\tkdrop`).

## 실제 노트북에서 확인할 것 (테스트 체크리스트)

빌드 환경에는 블루투스가 없어서 프로토콜·파일 처리·단일 exe 패키징만 자동 테스트됩니다. 다음은 실기에서 확인이 필요합니다.

1. **페어링 목록**: 양쪽 `상대 노트북 선택…` 에 상대 노트북이 나타나는지. (PC가 아닌 장치는 `(PC 아님)` 으로 표시)
2. **수신 대기**: 트레이 아이콘에 마우스를 올리면 `tkdrop - 수신 대기 중` 이 보이는지. `블루투스 수신 대기 실패` 가 보이면 블루투스가 꺼져 있거나 드라이버 문제.
3. **첫 전송**: 작은 텍스트 파일 하나 → 받는 쪽 `바탕화면\tkdrop` 에 저장되고 알림이 뜨는지. 받는 쪽에 상대가 자동 등록됐다는 알림이 뜨는지.
4. **양방향**: 반대 방향으로도 보내지는지.
5. **텍스트**: 클립보드 텍스트 보내기 → 받는 쪽 클립보드에 들어가는지 (메모장에 붙여넣기).
6. **여러 파일 / 폴더 / 한글 파일명 / 0바이트 파일 / 같은 이름 파일** (`이름 (1).확장자` 로 저장되는지).
7. **속도**: 5~10 MB 파일로 체감 속도 확인. Windows RFCOMM은 보통 초당 100~300 KB 정도입니다.
8. **실패 상황**: 상대 tkdrop 종료 후 보내기 → 몇 초~20초 안에 실패 메시지가 뜨는지. 상대 블루투스 끄고 보내기 → 실패 메시지.
9. **절전 복귀**: 노트북을 재운 뒤 깨우고 받아보기 (복귀 5초 후 수신 대기를 자동 재시작합니다). 블루투스를 껐다 켠 뒤에도 30초 안에 다시 `수신 대기 중` 이 되는지.
10. **차단**: 페어링된 다른 PC(또는 폰 앱)로 연결 시도 시 `연결 차단` 알림이 뜨는지. (가능할 때만)
11. **알림 클릭**: 파일 수신 알림을 클릭하면 탐색기가 그 파일을 선택한 채 열리는지. Windows 알림 설정에서 tkdrop 알림이 꺼져 있으면 풍선이 안 보일 수 있습니다.
12. **자동 실행**: 체크 후 재부팅하면 트레이에 올라오는지.

## 직접 빌드

Windows에서 .NET SDK(8 이상) 설치 후:

```bash
dotnet build tkdrop/tkdrop.csproj -c Release
```

결과물: `tkdrop/bin/Release/net48/tkdrop.exe` (32feet.NET 라이브러리는 exe 안에 포함됩니다. 옆에 생기는 `InTheHand.Net.Bluetooth.dll` 은 복사하지 않아도 됩니다.)

자체 테스트: `tkdrop.exe --selftest report.txt` (종료 코드 0이면 통과)

## 구현 메모

- C# / .NET Framework 4.8 / WinForms, 블루투스는 [32feet.NET](https://github.com/inthehand/32feet) (`InTheHand.Net.Bluetooth` 4.2.5)
- 클래식 블루투스 RFCOMM, 서비스 UUID `a4f1c0de-7d0b-4c6a-9e2f-3b5d8a1c0f42`
- 같은 exe가 양쪽에서 서버(수신 대기)와 클라이언트(보내기) 역할을 모두 합니다. 보낼 때만 연결하고 끝나면 끊습니다.
- 프로토콜: `TKDP` 매직 + 버전, 항목(파일 이름/크기/데이터/SHA-256 또는 텍스트) 반복, 항목마다 ACK
